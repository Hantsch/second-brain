## Requirement

Small gaps the S19 reviews left open. Each is real but decision-free; refine decides which are worth a story.

- Release runner: the post-push `gh` recovery hint prints paths that vanish with the CI runner; `electronBuilderCli` is duplicated from `scripts/handoff.mjs`; the `currentVersion` regex in `plan.mjs` is unanchored.
- Update service: electron-updater starts the installer one tick before `app.quit()` fires, so a task starting in that tick is vetoed by close-guard mid-install; a download re-checks and may fetch a newer version than announced; a timed-out check keeps running underneath; a manual-check IPC rejection has no UI; `service.ts` is ~320 lines (soft limit 300); three hand-rolled progress bars remain besides the new `ProgressBar` atom; `formatDateTime` resembles `HealthCard` `stamp()`.
- Tests: `start()`/will-quit wiring and the real `isSupported` gate in `services.ts` are not asserted directly. `tests/renderer/journal.test.tsx` ("bricht mit Enter, Shift+Enter und Ctrl+Enter nur die Zeile um") timed out once under full-suite load and passed alone.

## Acceptance Criteria

- [x] **AC1** — When `gh release create` fails after the push in CI, the recovery hint names the assets and the notes file by repo-relative paths and names the workflow artifact that holds them; the release workflow uploads exactly those files when the release step fails.
- [x] **AC2** — The release plan reads the current version from package.json's top-level `version` field only: a nested `"version"` that appears earlier in the text does not win.
- [x] **AC3** — A download whose re-check finds a different version than the one announced fetches nothing; the update returns to `available` and the offer is refreshed to the version the feed now names.
- [x] **AC4** — Once an install-and-restart has passed the restart-blocker check, the quit it triggers is not vetoed by the close guard, even if a task started in between.
- [x] **AC5** — An install whose `quitAndInstall` throws leaves no quit authorisation behind: the next close with a running task is asked about again.
- [x] **AC6** — A manual update check whose IPC call rejects shows an error line in About › Updates instead of nothing.
- [x] **AC7** — Every `progressbar` in the renderer is rendered by the `ProgressBar` atom; the three hand-rolled copies (local runtime install dialog, local runtime pull list, source job list) are gone.
- [x] **AC8** — The real `isSupported` gate in `services.ts` reports `unpackaged` for an unpackaged app, `demo` on the demo vault, and supported for a packaged app on a real vault.
- [x] **AC9** — `start()` schedules the startup update check once, and `will-quit` after a started app stops the update service.
- [x] **AC10** — The journal test "bricht mit Enter, Shift+Enter und Ctrl+Enter nur die Zeile um" asserts the same behaviour without typing long strings key by key, so it no longer depends on full-suite load.

## Open Questions

## Decisions (Sprint)

- **Scope:** all named gaps are in except the timed-out check (below); the sprint goal says the S19 gaps get closed, and each remaining item is a bounded fix.
- **Timed-out check is not fixed, only documented:** electron-updater's `checkForUpdates` has no cancellation and dedupes concurrent calls itself, so a late answer is already harmless and discarded by design; D2 adds a why-comment at `callChecker` instead of code.
- **Recovery hint via workflow artifact:** the runner writes the notes to `dist/release-notes.md` (gitignored, and `git add` names only three paths) and the workflow uploads assets + notes with `if: failure()`, because without an upload the files are gone with the runner and no printed path can help.
- **Version read reuses `applyVersion`'s top-level regex:** the read and the write must agree on which field is "the" version, so one exported pattern serves both.
- **`electronBuilderCli` moves to `scripts/lib/electron-builder-cli.mjs`;** handoff wraps its throw in `HandoffError`, so its step-tagged message stays as it is.
- **A superseded download fetches nothing and re-checks:** the backend compares the re-check's version with the announced one before downloading, and the service then runs a manual check so the new offer (with its notes) replaces the old one — no new i18n string, because the user sees the ordinary "available" state of the newer version.
- **Install/quit race is closed by authorising the quit, not by freezing the queue:** the user already confirmed the restart and the blocker check passed, so the close guard treats it like a confirmed quit; a task that starts in that tick is cancelled by `will-quit`'s existing `cancelAll('shutdown')` net, exactly as on any confirmed quit, which is safer than an installer overwriting a running app.
- **The authorisation is revoked when `quitAndInstall` throws,** because a lingering `confirmed` flag would let a later close kill a running task unasked.
- **`service.ts` split:** download/cancel/install staging moves into `src/main/update/staging.ts`; the service keeps check/state, so each file has one responsibility and both stay under 300 lines.
- **`HealthCard`'s `stamp()` is replaced by `formatDateTime`;** Intl's own date-time joiner replaces the hand-built `", "`, which is the same visible text in de and en.
- **Meters stay as they are:** `HealthMeter` and `ProposalCard`'s `sb-meter-fill` are score meters, not progress bars, so they are out of AC7.
- **AC6 is proven by a renderer test, not e2e:** main's `update:check` never rejects by contract, so a rejection cannot be produced through the real surface; the behaviour under test is the renderer's handling of a rejected call.
- **Journal flake is fixed by typing less, not by a longer timeout:** text goes in via `userEvent.paste`, only the Enter combinations are typed, and the assertions stay unchanged.

## Plan

1. **Release scripts (D1):** shared `scripts/lib/electron-builder-cli.mjs`; `currentVersion` reuses the exported top-level version pattern from `version.mjs`; notes go to `dist/release-notes.md`; the post-push hint prints repo-relative paths plus the artifact name; `release.yml` gets an `if: failure()` upload step.
2. **Service split + superseded download (D2):** extract `staging.ts` from `service.ts`; `UpdateBackend.download` takes the expected version and returns `{ kind: 'superseded' }` without downloading when the re-check names another; the service then re-checks. Why-comment on the timed-out check.
3. **Install authorises the quit (D3):** `close-guard.ts` exports `authoriseQuit(): () => void`; the update service gets an `authoriseQuit` option, wired in `services.ts`; staging calls it right before `quitAndInstall` and revokes on throw.
4. **Wiring tests (D4):** `isSupported` gate in `services.test.ts`; startup check + will-quit stop in `start-without-tray.test.ts`.
5. **Renderer (D5):** `UpdateCheckRow` shows an error line on a rejected check; three progress bars → `ProgressBar` atom with a source-scan test; `stamp()` → `formatDateTime`.
6. **Journal flake (D6):** paste instead of type.

Order: D1 and D4–D6 are independent; D3 needs D2's `staging.ts`. Changelog: D2, D3, D5 each add one `Fixed` bullet under `## [Unreleased]` in `CHANGELOG.md`.
